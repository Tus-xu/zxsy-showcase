## 0. 结论摘要（供主控 30 秒校准）

1. **统一的是字体、色彩语义、布局尺度、组件细节和产品语言，不是所有消息的形状**。AI 文字层默认无边框、无底色、无阴影；边界只出现在「需要被当作对象操作」的组件上。
2. 回答分七类：微答 / 解释 / 解题 / 诊断 / 实验 / 练习 / 记录；对应四档视觉重量 W0–W3。任何一类都不能套用另一类的模板，尤其禁止「每条回复 = 标题 + 表格 + 图 + 练习 + 总结」。
3. 消息按四层解剖：元信息层（头像/名称/时间）、文字层（Markdown/公式/表格）、组件层（图/题卡/练习/引用/学习卡）、操作层（复制/重生成/反馈/时间戳）。四层各自有独立规则，互不代偿。
4. 正文 15px / 28px（`--text-15`、`--leading-chat`）；内容列 860px（`--dialog-column`）；正文测量宽 720px（新增 `--reading-measure`，待实验 E3）；标题 18/16/15px；表格 14px；时间戳 11px；操作按钮 26×26px。
5. 长回答需要「锚点」但不能回到整条白卡：默认用 2px 左轨（`--brand-faint`）+ 18px 左内距；短答无边框或弱底；组件各自 1px 轻边界。此条是 L5 对 L1/L4 的裁决，仍需 E1 实验复核。
6. 生命周期必须有真实状态：思考态（仅 `streaming && !text`）→ 流式（光标、可停止）→ 停止（保留部分文本 + 「已停止回复」）→ 完成（操作条出现）→ 失败/边界（一行说明，不伪装成正常回答）。禁止伪造推理过程、工具执行、引用或学情。
7. 外壳继承原产品：240px 侧栏、置顶/今天/7 天内分组、紫色「＋ 新对话」、底部宽输入卡、π 标识与品牌紫；空会话保留「今天想搞定什么数学题？」与四入口，不做仪表盘式对话页。
8. 硬性否决（来自 L5）：常驻阶段徽标/步骤编号/「原题暂停在」/题干线索表；整条回复包卡；选项做成整行表单；「掌握 +1 / 已计入学情 / 已自动收录 / 明晚提醒」等无事实支撑的统计；界面操作生成学生气泡。
9. 待实验项 9 个（E1–E9），每个都给了两种候选、判定截图和通过标准；未实验前不得写成「所有回复必须/必须无边框」。
10. 本轮亲自 Read 查看 23 张截图（§8），覆盖当前（1440/1920）/ V3/V5（1440/1920）/V6（1440/1920）/原项目/通用智能体/开源/数学工具；结论均可回溯到路径或证据编号。

### 1.2 冲突裁决顺序（可直接执行）

当两条规范冲突时，按以下顺序裁决，并在实现 PR/截图中注明引用了哪一条：

1. **L5 否决**：违反 §0 第 8 条硬性否决的，直接不做，不论 L1/L2/L4 多喜欢。
2. **L4 只保护外壳与品牌**：侧栏宽度、分组、品牌紫、π、输入区形态、空会话四入口；不保护「每条 AI 都要气泡」「每条都挂 AI 生成」这类消息形状。
3. **L2 决定内容形态**：先确定这条回答是七类中的哪一类、需要多长、是否引用学生原话，再选视觉。
4. **L3 决定数学渲染**：行内公式、展示公式、表格、最终答案框、图形对象色，按数学工具证据。
5. **L1 决定交互细节**：操作条何时出现、工具活动如何折叠、滚动何时暂停、输入区如何停止。
6. **仍未定的，进入 §9 实验**：不能凭「更现代/更高级」直接实施。

## 2. 消息解剖：四层结构与样式规则

### 2.1 解剖图

```text
┌─ 用户轮 ────────────────────────────────────────────────────────────┐
│  [附件层]  题图/文件缩略：气泡外，max 460px，1px --border，radius 12 │
│  [气泡层]  文字 14px/1.75，--brand-soft 底 + --brand-faint 边       │
│            radius 16 16 5 16，padding 10 15，max min(77%,645px)     │
│  [操作层]  hover：复制 / 编辑 + 时间 11px --ink3                    │
└──────────────────────────────────────────────────────────────────────┘
┌─ AI 轮 ─────────────────────────────────────────────────────────────┐
│  [元信息层]  π 头像 32×32 + 名称 13px/700 + 可选状态（一次）         │
│  [文字层]    15px/28px --ink，无边框/无底色/无阴影，measure 720px    │
│              ├ 段落 / 标题 / 列表 / 引用块                          │
│              ├ 行内公式 / 展示公式块 / 表格                          │
│              └ 来源引用（真实才显示）                                │
│  [组件层]    图 / 题卡 / 练习 / 引用 / 学习卡：各自 1px 轻边界        │
│  [操作层]    复制 / 重新生成 / 版本 / 赞踩 + 时间；hover 或最后一条  │
└──────────────────────────────────────────────────────────────────────┘
```

## 4. 七类回答形态与视觉重量

### 4.1 与 V6 `data-mode` 的映射

V6 的 6 种模式（`01` §6.8；V6 `preview.js:360`，data-mode：compact / editorial / lab / feedback / practice / record）是正确方向，但仍是原型。本文扩展为 7 类，把「解题」从 editorial 中独立出来，因为它的答案收束、步骤标题、公式密度与概念解释不同。

| 本文七类 | V6 对应 | 视觉重量 | 一句话定义 |
|---|---|---|---|
| 微答 | compact | W0 | 1–3 句，直接回应，不展开 |
| 解释 | editorial | W1 | 概念/原理，2–4 个分节，允许 1 表 1 图 |
| 解题 | editorial（solution 子型） | W1–W2 | 已知/所求 → 步骤 → 答案框 → 一处核对 |
| 诊断 | feedback | W0–W1 | 引用学生原话 → 定位一处错误 → 一个问题 |
| 实验 | lab | W3 | 一句话设定 + 可操作图形 + 读数 + 追问 |
| 练习 | practice | W2 | 题卡 + 选项/作答 + 判定 + 提示入口 |
| 记录 | record | W0–W1 | 只写实际发生的事，3–5 条或小表 |

### 4.2 微答（compact / W0）

| 项 | 规范 |
|---|---|
| 触发 | 问候、确认、单点事实、概念一句话、追问的追问；用户问题可用 1–3 句答完 |
| 结构 | 第 1 句直接回答；第 2 句给依据/条件；第 3 句最多一个追问或邀请。**无标题、无列表、无表格、无图、无卡** |
| 长度 | ≤120 个中文字符；超过则升级为解释 |
| 视觉 | 无边框、无底色、无阴影；正文 15/28；可含 1 个行内公式；最多 1 个行内代码 |
| 操作 | 仅复制 + 时间；不显示重新生成/赞踩等多余按钮（全局 AI 标识按 §2.4） |
| 禁止 | 禁止 h2/h3；禁止「首先/其次/最后」三段式；禁止「希望这对你有帮助」；禁止为了凑视觉加图/卡；禁止每条都追问 |
| 证据 | L2 S1（197 tokens 的三步路线仍偏长）、`07` §3.2（108–113 字短答存在）、`[ORIG-QA]` 短答一段、`[CUR-S2]` 当前长答反例 |
| 冲突取舍 | L4 原项目短答也有气泡；本文默认无边框，E4 实验「弱底 vs 无底」 |

### 4.3 解释（editorial / W1）

| 项 | 规范 |
|---|---|
| 触发 | 用户问「为什么/怎么理解/有什么区别」；需要定义 + 例子 + 边界 |
| 结构 | 1 句承接（引用学生上一句/上一个式子）→ 1 句总述 → 2–4 个 h3 分节 → 1 句收束/追问。每节 1–3 段，至少一节含公式或对比 |
| 长度 | 200–600 字；超过 600 字必须拆成两轮或改为解题 |
| 视觉 | 文字层无边框；≥3 个内容块或 >200 字时启用左轨：`border-left:2px solid var(--brand-faint); padding-left:18px`（只包正文块，不包操作条）；标题 18/16；允许 1 张表或 1 张图 |
| 组件 | ≤2 个；图/表放在相关小节之后，不先放图再解释 |
| 禁止 | 禁止「定义/性质/例题/总结」四段模板每条都用；禁止把粗体当标题；禁止无引用学生原话；禁止把 6 个知识点塞进一条 |
| 证据 | `[V5-S01]` 单卡长文（反例：容器统一）；`[V6-PHOTO]` 分节+公式块；`07` S2/S7 的真实长答结构；F2/F3 |
| 冲突取舍 | L1 ChatGPT 无边框 vs L5 F3 长答需锚点；采用左轨，E1 实验 |

### 4.4 解题（solution / W1–W2）

| 项 | 规范 |
|---|---|
| 触发 | 用户要求「解这道/看完整过程/检查我的解法」；拍照题解析 |
| 结构 | ① 已知/所求各一行（可用小表或两行文字）→ ② 2–5 个 h3 步骤（每步只做一件事）→ ③ 答案框 → ④ 一句核对/易错点。步骤标题用「求导」「定号」「比较」，不用「第一步/Step 1」 |
| 长度 | 400–900 字；步骤 >5 时合并或拆轮 |
| 视觉 | 左轨同解释；公式块每步最多 1 个；答案框按 §3.5.3；允许 1 张图（函数图/几何图）贴在相关步骤后；**无进度条、无阶段 chip、无「共 N 步」** |
| 组件 | 图 1 + 答案框 1；不再叠加练习卡 |
| 禁止 | 禁止「读题/选方法/分步推导/订正」阶段标签；禁止把题干再抄一遍成长表；禁止用「掌握度」收尾；禁止每题都配图 |
| 证据 | MTH-20（分步+方框答案+内嵌图）；`[V6-PHOTO]` 分节；`[CUR-1920]` 的「题干线索」表是反例；F1/F4 |
| 冲突取舍 | L3 数学工具鼓励图，L5 反卡片通胀；限制 1 图 |

### 4.5 诊断（feedback / W0–W1）

| 项 | 规范 |
|---|---|
| 触发 | 学生答错/步骤错/问「我哪错了」；系统检测到与目标不一致 |

### 5.2 内联规则（可直接编码）

1. **组件只包住组件本身**：组件根节点可以有 1px 边界、圆角、内距；其父 `.ai-bubble` 必须保持无边界（§2.5）。
2. **组件出现在相关文字之后**：先解释「看什么」，再放图/练习；唯一例外是拍照题解析的题卡可以先出现，因为题面是上下文。
3. **标题只在组件有独立语义时出现**：图有 `caption`、练习有「练一题」、引用有资料名；普通公式块、表格、段落不加标题。
4. **嵌套降级**：组件内再放组件时，内层去边框、去白底、改用 `--bg` 弱底；不允许双边框（V6 `[V6-GUIDE]` 的「面板内再套卡」是反例）。
5. **数量上限**：单条 AI 回复 ≤2 个组件；组件内子块不计，但不得形成 3 层视觉容器；超过则拆轮。
6. **引用**：只显示真实来源；正文用 `【1】` 与 chip 对应；无来源时写一句「本题未引用资料」，不摆空 chip；最多 4 个（C8）。
7. **练习**：选项用胶囊/按钮，不用 `<input type=radio>` 整行表单；点击后原地显示判定，不生成学生长句气泡；如需记录作答，用卡片内状态或一条紧凑学习事件（F11；`09` §3.7）。
8. **图**：图内对象颜色只表达对象身份；对错色不进入画布；图上标注字号 ≥11px；坐标轴/网格线用 `--border`/`--line2`，不用纯黑。
9. **学习卡**：只汇总真实发生的事件；数字必须有来源；没有数据时写「本次没有记录」，不画空表。
10. **附件**：题图放用户气泡外，白底 1px 边界；文件 chip 220px 单行；不把附件塞进 AI 回复卡。

### 5.3 禁止事项

- 禁止把整条 AI 回复包进任何卡片、面板、`reply-panel`、`ShowcaseStageCard` 外壳。
- 禁止组件套组件超过 1 层；禁止「外卡 + 内卡 + 选项 + 解析 + 步骤条」的 V4 式五层结构（F4）。
- 禁止在每个组件上重复「AI 生成 / 已核对 / 离线」标签；全局标识按 §2.4。
- 禁止用卡片数量表达「内容丰富」；一条回复最多一个主要意图。
- 禁止把表格当布局容器；禁止把选项做成表格行。
- 禁止组件出现时与用户提问无直接关联（F4/F11；task §8.2）。

### 6.2 思考态与流式的硬规则

1. 思考态只在**没有任何文本**时出现；一旦有 token，立即换成正文，不能同时显示 spinner 和正文。
2. 不展示 chain-of-thought、内部 stage、工具参数；如果未来接入真实思考内容，必须由真实 `thinking` 事件驱动并默认折叠，不得人工编写。
3. 流式期间操作条隐藏（`hideWhenRunning`），防止用户在生成中复制半句；停止按钮在输入区，不在消息上。
4. 流式文本不得整段突然出现；离线 `session.toEvents` 必须分片（W3 Step 1），每片 6–30 字，不切断 `$...$`/`$$...$$`。
5. 公式流式容错：未闭合 `$$` 临时闭合，结束后重渲一次；不得出现整段空白（ChatGPT 流式空窗是反例，E-R5-03）。
6. 光标只在流式尾块出现；`prefers-reduced-motion: reduce` 时取消闪烁动画（保留静态光标或隐藏）。

### 6.3 操作条的出现/消失矩阵

| 消息状态 | 复制 | 重新生成 | 版本 | 赞/踩 | 时间 | 求助文字 |
|---|---|---|---|---|---|---|
| 流式中 | 隐藏 | 隐藏 | 隐藏 | 隐藏 | 隐藏 | 隐藏 |
| 完成（在线/录制） | 显示 | 显示 | >1 版本显示 | 显示 | 显示 | 仅 socratic 且未结束 |
| 完成（离线预设） | 显示 | **不显示**（不伪造重生成） | 不显示 | 显示（本地记录） | 显示 | 显示（如适用） |
| 已停止 | 显示 | 显示（如支持） | 按版本 | 显示 | 显示 | 显示 |
| 失败 | 显示 | 显示（重试） | 不显示 | 隐藏 | 显示 | 隐藏 |

### 6.4 滚动与「回到最新」

- 跟随阈值：距底 ≤72px 视为跟随（`DialogView.vue:391-401`）。
- 用户上滚、打开折叠、键盘滚动、触摸上滑 → 暂停跟随；内容增长不得把用户拉回底部（`03b` E1/E2，本地实测 `local-08/09`）。
- 只有新 run 开始、切换会话、点击「回到最新」才恢复跟随。
- 「回到最新」按钮：34px 高，12px 字，`--card` 底 + `--line` 边 + `--shadow-sm`，距输入区 10px；有未读时文案「查看新回复」（`DialogView.vue:1007-1011`）。
- 历史前插：加载更早消息时用首条消息锚点保持 scrollTop，不跳动（`03b` E3；`DialogView.vue:403-411`）。
- 流式插入大图/卡片时，ResizeObserver 只在跟随状态滚底；用户已上滚则保持位置。

### 6.5 失败/边界文案纪律

- 失败：说明「发生了什么 + 可以怎么做」，例如「这段讲解没有加载完整，可以重试或换个问法。」不写「系统错误 500」。
- 边界：具体说明覆盖范围，例如「当前示例覆盖这道三次函数题的引导，你可以点题卡继续，或换一道题。」不写「我不知道」；不重复整张原卡（F5；`09` §3.8）。
- 离线：首次进入时用 header details 说明「预设练习和已录制讲解」；不假装在线模型；不显示「线路波动」等环境降级文案（`07` §3.9）。

- S1 微答：无标题、无卡、≤120 字；与长答同屏对比重量差。
- S2 解释：左轨/无轨按 E1；h2/h3 层级；1 表或 1 图。
- S3 解题：步骤标题、答案框、1 图；无阶段 chip。
- S4 诊断：引用学生原话、一处定位、一个问题；无红底大卡。
- S5 实验：拖动前后两帧 + 读数变化；真实数值。
- S6 练习：题卡 + 胶囊选项 + 判定行 + 提示；无假统计。
- S7 记录：3–5 条真实事件；无掌握度断言。
- L1 思考态 / L2 流式（含光标）/ L3 停止 / L4 完成操作条：各 1 张。
- 1920×1080：S2 + S6 各 1 张，列宽仍 860、无水平滚动。
- 200% 缩放：S2 一张，无内容遮挡、无横向滚动。

### 10.3 内容验收

- 每条 AI 回复第一句引用/承接学生上一句（原话、选项、式子、数值）至少一处。
- 一条 6 轮会话至少 2 条 W0 微答；不得 6 条同形。
- 一次只问一个问题（诊断/引导）。
- 无「好的/希望有帮助/总之」模板腔；无未审核的模型自我纠错长文。
- 无假工具、假引用、假学情、假时间、假「学生已完成」。
- 引用 chip 与正文编号一一对应；无来源时写「本题未引用资料」。
- 练习判定有文字定位，不只是红叉/绿勾。

### 10.4 视觉审核（人）

- 主控亲自查看 7 类形态 + 4 个生命周期状态的原图，不接受缩略图/文字总结。
- 以 1440×900 灰度缩略图检查「重量差」：微答 vs 实验必须在 1 秒内看出不同。
- 以 1920×1080 检查内容列不漂移、侧栏不拉宽、输入区不遮挡。
