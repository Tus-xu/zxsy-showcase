## 0. 结论摘要

1. 学生端对话主链路是 `DialogView.vue` + `MessageBubble.vue` + `useChat.js` + `messageModel.js` + `offline/replay.js` + `offline/showcase/*`。消息协议已经有较好的分层：SSE 事件归约 → 统一消息模型 → 卡片组件分发，具备增量流式渲染组件 `IncrementalMarkdown.vue`。
2. 离线“教学示例”另有一条本地状态机：选项点击不是本地状态更新，而是把选项文案当作学生消息发出去，再走 `POST /api/agent/chat` 的离线回放；这是“像在操作表单”的主要来源（`ShowcaseStageCard.vue:277-302`、`MessageBubble.vue:667-676`、`DialogView.vue:494-507`、`useChat.js:329-420`）。
3. “脚本感”最大的技术来源不是卡片组件，而是示例状态机的输出形态：每个节点固定返回 `progress + card(s)`（`engine.js:135-143`、各 `node(...)` 的 `build`），且 `session.toEvents` 把整段回答作为**单个 token 事件**下发（`session.js:233-241`），导致“流式”实际是整段文字突然出现；真实采证 flow-A 中有 318 个 token 事件，形成对照。
4. 第二个来源是关键词/同义短句匹配：`norm/has/matchOption/isLimitAsk` 只处理去空白、去标点、精确同义词（`engine.js:307-342`），超出范围就回到固定兜底句并重复原卡（`session.js:168-174`、`engine.js:129-130`）。截图中“今天天气不错”得到“这条练习里你可以先选一个步骤”并重复整张读题卡，即此机制。
5. 第三个来源是常驻状态徽标与固定统计：顶部阶段徽标（`DialogView.vue:311-340`）、过程条（`MessageBubble.vue:55-66`）、卡片内“原题暂停在”“AI 生成”等标签，以及“掌握 +1 / 已计入学情 / 已收录错题本”的文案（`QuizSetCard.vue:62-64,216-220`）在离线路径下并未真正更新学情或错题本（`session.js:91-105`、`replay.js:264-269`）。
6. 安全改造方向：先改“生成与呈现节奏”（在 `session.toEvents` 分段发 token，复用 `IncrementalMarkdown`），再改“内容与选项语义”（减少每题同一模板、把非对话操作留在组件内），最后才扩新卡型。新卡型有清晰插入点，但必须避开 `GenericCard` 兜底和 QA DOM 选择器。
7. 单测基线：`pnpm exec vitest run --config vitest.offline.config.ts` 为 **6 个测试文件、88 个测试全部通过**（4.19s）。

## 3. “脚本感”来源清单（带精确代码位置）

> 说明：以下“脚本感”不等于全部是缺陷。离线演示需要在无模型、断网条件下可控运行，部分固定文案/固定流程是合理的。表中同时标注“可接受”与“优先改造”。

### 3.1 关键词/同义短句匹配，无法承接自然表达

- `engine.js:307-315` 的 `norm` 把输入压成“无空格、无标点、无括号引号、小写”的字符串；`322-329` 只做 label/id 精确匹配或 aliases 唯一匹配；`340-342` 的 `isLimitAsk` 只认四个关键词。示例：`a2_diagnose` 只有 `picked.id === 'slope'` 才认为答对，其他“负/小于0/小于零”走澄清或提示（`engine.js:531-554`）；`a4_why` 只接受“左…右…升/增…降/减”的极窄自由文本（`729-730`）。
- `handlers/agent.js:105-116` 的采证回放匹配要求 `normalizeInput(actual) === normalizeInput(recorded)` 或等于 `turn.input`；对真实用户输入几乎只能精确复现，超出就返回“没有对应的录制讲解”（`replay.js:253-261`）。
- `session.js:168-174`：非示例会话或状态不可继续时，固定返回“这次提问没有预设讲解……”。
- 影响：不同说法（“这一步为什么不是极小？”“我还是不懂”“能换个讲法吗”）可能落不到对应教学分支，或反复触发同一条提示；这是“关键词脚本”的直接体感。
- 改造方向：优先扩充“意图族”而不是无限加同义词；对无法判定的输入，给出真实能力边界 + 可继续的局部动作，而不是重复原卡。参考需求 `task-original.md` 第 10.3 节。

### 3.2 固定文案与固定卡片模板

- 全部教学文案集中在 `engine.js:33-131`（`T` 对象），每个节点引用固定字符串；卡片由 `progress`（`135-143`）、`cardRead`（`145-164`）、`cardLocal`（`166-179`）、`cardMethod`（`181-193`）、`cardDerive`（`195-197`）、`cardLesson`（`199-217`）、`cardCheck`（`219-221`）、`cardConclusion`（`234-243`）、`cardFix`（`245-254`）、`cardRetry`（`256-270`）、`cardSummary`（`272-281`）、`cardLimit`（`283-301`）、`cardEntry`（`901-910`）、`cardInvite`（`979-991`）、`cardTally`（`993-1002`）等构造。
- 每个节点的 `build` 几乎都是 `{ text: T.x, cards: [progress(...), card...] }`，例如 `407-408`、`426-427`、`453-454`、`475-490`、`508-530`、`590-605`、`625-639`、`652-666`、`679-695`、`710-724`、`743-757`、`771-787`、`801-816`、`829-846`、`863-867`、`880-881`、`912-916`、`925-930`、`1004-1005`、`1025-1026`、`1053-1057`、`1073-1089`、`1104-1108`、`1125-1142`、`1170-1174`。
- 预置轮次同样固定：`transcripts.js:52-81`（S1）、`85-114`（S2）、`118-139`（S3）、`143-153`（S4）、`157-186`（S5）、`190-201`（S6）、`205-240`（COMBO）。
- 影响：同一会话每次演示得到相同文案/相同卡片顺序；改动一个节点容易造成上下文断裂。
- 改造方向：把“节点文案”升级为“可组合的内容块”（自然语言段 + 公式 + 图形 + 操作），并在节点内按 `facts/path/lesson` 选择不同表达；同时保留纯函数可测试性。

### 3.3 showcase 没有真正的 token 流式

- `session.js:233-241` 的 `toEvents` 只 push **一个** `token` 事件，`data.text` 是整段 `aiTurn.text`。
- `replay.js:104-134` 的 `sseResponse` 每 8ms 推一个事件；`replay.js:250-252` 对 showcase 固定 `delayMs: 8`。因此“流式”是事件间隔，不是 token 粒度。
- 真实采证对照：`app/src/offline/fixtures/student/flow-A.json` 含 318 个 `event: token` 块（本次用 PowerShell 统计）；说明真实 SSE 是逐 token 的，而示例状态机是一次性。
- `IncrementalMarkdown.vue:37-92` 已具备按块增量渲染、尾块重绘、rAF 节流能力；当前瓶颈在事件源，不在渲染器。
- `session.runTurn` 在返回事件前已经把完整 AI 轮次持久化（`session.js:188-208`）；`ChatInput` 的“停止”只会中止回放定时器/网络流（`replay.js:111-128`、`useChat.js:423-431`），不会让生成“停下”。这与真实模型“停止生成”的语义有差距。
- 改造方向（首选）：在 `session.toEvents` 将 `aiTurn.text` 切成 token/短句序列，按自然停顿（标点/公式块）分批发 `token`；卡片事件在文本之后或与文本交错（需保持历史 `toHistoryItems` 的 block 顺序）。不改协议、不改渲染器。次选：在 `replay.sseResponse` 对已录制的 `token` 事件重放节奏（但示例仍只有一个 token，无法产生真实逐字感）。

### 3.4 回复同构：每条 AI 回复几乎都是“progress + 卡片”

- 示例引擎所有回复都附 `progress(...)`（`engine.js:135-143`），多数还附一张 `showcase_stage` 卡；即使 `done`/`s6_done` 也保留进度（`925-930`、`967-975`）。MessageBubble 对 `showcase_stage` 会隐藏 `socratic_progress`（`MessageBubble.vue:126`），但顶部仍显示阶段徽标（`DialogView.vue:311-340`）。
- `socratic_progress` 的 `steps_count: 4` 是固定的（`engine.js:137-140`），而状态机实际有 28 个节点（`engine.js:407-1182`）；它表达的是“四阶段”，不是真实步数。离线时 `DialogView` 用 `stage_label` 只显示阶段名（`DialogView.vue:320-321`），但 `progress` 数据本身仍是固定四步；如果未来去掉 `stage_label`，会出现“第 N 步 / 共 4 步”的伪精确。
- 影响：每一轮视觉骨架相同，学生感受不到“简单问答/复杂解析/短追问”的形态差异，违背需求 9.3 的“不同回答形态”。
- 改造方向：把 `progress` 从“每条必带”改为“仅在阶段真正变化时带”；按回复类型决定是否带卡（纯文本问答、简短追问、完整解析、错因复盘分开）。这是低风险、高收益改造。

### 3.5 常驻状态徽标与“仪表盘”感

- 顶部阶段徽标：`DialogView.vue:16-19`、`311-340`；离线还会显示“离线体验”details（`20-23`）。
- AI 消息过程条：`MessageBubble.vue:55-66`（`status` 事件折叠面板），卡片标签：`116-123`、`125-141`。
- 卡片内“原题暂停在 · …”：`ShowcaseStageCard.vue:15`；`pauseAt` 在 `engine.js:204`、`282`、`1079` 等出现。
- “AI 生成 · 仅供参考，请核实”：`MessageBubble.vue:323-328`、`AiGeneratedMark.vue:12-31`；`QuizSetCard.vue:10-12` 另有“AI 生成”标签；`MathFigure.vue:29-33` 有“已核对原题图”徽标（仅当 `problem_source_sha256` 存在）。
- 影响：多个常驻标签把教学对话变成“系统状态面板”，且部分标签（“已核对原题图”）在没有对应字段时不会出现，但一旦出现需要真实依据。
- 改造方向：状态退到背景（如仅在阶段变化时一次性提示），保留必要的离线说明；不要在每个回复上重复技能/模型/生成标识。

### 3.6 “假统计/过度承诺”文案

- `QuizSetCard.vue:62-64`：答对显示 `+1 掌握`，答错显示 `-1 需复习`；`216-220`：答对“掌握 +1，已计入学情”，答错“已自动收录错题本，明晚提醒复习”。离线路径下：
  - `DialogView.onQuizAnswered` 调 `studentApi.reportLearningEvent`（`DialogView.vue:692-707`）；
  - `replay.dispatch` 对 `/api/student/learning-events` 只调 `logQuizAnswer`（`replay.js:264-269`）；
  - `logQuizAnswer` 只写 `quizLog`（`session.js:91-105`），不更新 BKT/学情接口，也不写错题本；
  - 错题本只有 `s6_entry` 的“加入错题本”动作会写 `errorBook`（`engine.js:948-965`、`errorbook.js:14-38`）。
  - 因此“已计入学情”“已自动收录错题本”“明晚提醒复习”在离线路径下是过度承诺；如果卡片来自真实后端则可能成立，但演示环境不能默认。
- `summaryOf` 的题数：`session.js:123-146` 的 `quizTally` 以 `QUESTIONS` 三道为分母；`engine.js:1204-1208` 输出“这三题已经作答 X/3 题。首答正确 X/3，订正后 X/3”。实测截图 `qa/student-chat-showcase/shots/shots/15-V04-c6-done.png`（本代理已查看）显示“这三题已经作答 1/3 题。首答正确 0/3，订正后 0/3。”，同一屏又显示“已订正”，读起来自相矛盾：学生只完成了引导题，却被用三题分母统计。
- 固定“几分钟前”：`catalog.js:20-70` 为 7 条示例写死 `minutesAgo`，`convItem` 用它生成 `created_at/updated_at`（`83-94`），侧栏的“今天/7 天内”分组因此是布景时间，不是真实学习时间。
- 预置“学生已完成”的剧本：`transcripts.js:190-201` 的 S6 首条用户消息直接声称“刚才第一道变式我第一次选了 A，现在知道应该选 C”；`errorbook.js:19-31` 预置 `first_choice:'A'/fixed_choice:'C'`；`META.s5.firstAnswer:'A'`（`transcripts.js:245-253`）。这是展示用预置历史，不是访客本次实际作答；如果演示时被理解成“系统记录了学生刚才的行为”，会触碰需求 8.2 的“学生未作答，AI 却声称学生已经完成”。
- 相对诚实的部分：`summaryOf` 只依据 `facts`（`engine.js:1186-1211`）；`knowledge.refs` 明确标注“自编讲义（本项目编写，非教材原文）”（`knowledge.js:83-94`）；`AiGeneratedMark` 明确标注 AI 生成。这些应保留。
- 改造方向：要么让离线统计只统计“本次真实发生的动作”（例如分母为实际作答数，或明确写“本示例共 3 题，目前作答 1 题”）；要么在文案上降级为“将计入学情/可加入错题本”，不要断言后台已发生；预置历史用“示例记录”标签或主持人说明区分。

### 3.7 非对话操作被转换成用户气泡

- 选项/动作：`ShowcaseStageCard.vue:153-168`、`184-207` → `pick/send`（`277-302`）→ `MessageBubble.onChoiceClick`（`667-676`）→ `DialogView.onSocraticChoice`（`494-507`）→ `useChat.doSend` push 用户消息（`useChat.js:347-350`）。每一次点选项都会生成一条学生气泡，即使它只是“看导数变号”“题目看懂了”。
- 出题卡出口：`onQuizExplain` 发送 `displayText: '💬 讲解这道错题 · 举一反三'`（`DialogView.vue:752-764`）；`onQuizMore` 发送 `displayText: '🔄 再来一组变式'`（`766-774`）；`onCompleteAction` 的“举一反三/出一道考考 AI”也发送长文本（`784-807`）；`onNeedProblem` 的“让 AI 出一道”发送长句（`558-573`）。这些按钮操作在视觉上变成“学生说了很长一句话”，不自然。
