### S4 · C 题收束轮：模型误解 X，并否认能看到原题（严重失败）

  > 如果 X 表示“抽到的号码”，且五个号码等可能，那么每个号码被抽到的概率都是 1/5，此时
  > $$E(X)=\sum_i x_i P(X=x_i)$$

  > 这里的关键是：五个号码的“取值”分别是多少？ 如果号码是 1,2,3,4,5，那均值是 3；如果号码是别的数，均值就不同。你写的 61/125 这个数，分子 61、分母 125 看起来像是“5 个号码的加权和 / 125”，这暗示每个号码概率是 1/125 而不是 1/5——这两者对不上。

  > 所以先问你两个问题：
  > 这题里 X 的取值具体是哪五个数？
  > 每个号码对应的概率是 1/5 还是别的？

  - **引用失败**：4 个教材 chip 被用来说明「资料没覆盖」，反而暴露引用是装饰性的；这正是「知识引用无实际来源」的反例。
  - **教学失败**：不接住学生正确的中间结论，转而要求重新列分布列，增加输入税；且一次问两个问题。
  - **价值**：这是本批证据中最有价值的「真实失败样本」——说明真实模型输出不能未经审核直接作为演示内容。

## 3. 横向分析（任务书 §7.2 的九个维度）

### 3.1 自然表达

- **有**：口语连接词（「咱们」「不着急」「哦，等一下」「顺便确认一下」）、对学生步骤的具体肯定（「你这一步化简得很干净」）、承认不确定（「我无法从资料里直接确认」）。
- **也有模板腔/机械重复**：多轮出现同一句式「你这一步…接下来…」「你写的 $X$…先回到…」；连续追问时缺少新信息。
- **与人工脚本的差别**：V5/V6/演示 transcripts 的句子更干净、更少口头语，但**过于稳定**，同一分支永远同一句；真实模型更自然，却会在不该口语的时候自我纠缠（S6）。

### 3.2 长度与结构变化

| 样本 | 输出量 | 结构 |
|---|---|---|
| A-t06（run-03 SSE） | `tokens_out=32`，一句话追问 | 单段 + 卡片 |
| A-t00（S1） | `tokens_out=197` | 3 步编号 + 邀请 |
| C-t05（run-03 SSE） | `tokens_out=58` | 肯定 + 两问 + 卡片 |
| S2（run-02 A） | 约 300–400 字 | 2 步推导 + 条件核对 + 难度行 + 4 chip |
| S7（conv-604ea8e7） | 822 字 | 定理 → 符号 → 对照 → 两个关键点 → 前提提醒 + 4 chip |
| conv-b2710c62 | 1091 字 | 长判定 + 坐标法验证 + 多选项讲解 |
| conv-fe3c4e7f | 108/113 字 | 短答，两轮各一段 |

- **结论**：真实模型确实有 32–197 tokens、108–1091 字的跨度；但**长答的结构高度相似**（「确认/复述 → 分步 → 结论 → 追问/提醒 → 难度行」），短答只在简单概念题出现。演示项目需要的是「按问题难度与教学阶段选择长度」，而不是随机变化。

### 3.3 上下文承接

- **好的案例**：`conv-0cd000d9` 16 轮内能引用学生上一轮 `BC⊥AA_1`；`conv-8e006e4c` 20 轮内引用「你刚才由虚轴长…正确写出了 b=√7a」。
- **坏的案例**：
  - A 题第二轮「我还没看到题目」（run-01 A-D1；run-02 B5 复现）。
  - C 题收束轮「资料没有覆盖这道具体题目，建议把原题贴出来」（S4）。
  - B 题首轮后学生描述题目，平台仍回「我还没看到题目」并下发门禁卡（run-01 B t1）。
  - 同一学生同一句话重复提交，模型几乎逐字重复回答（S8）。
- **根因线索（只读文档）**：V4/V5 设计文档承认 `qa_rag` 与 `socratic_solver` 分层、KC 标注 3s 超时、`kp_code` 为空即静默跳过 detour；`student.md` 要求「一次只问一个问题」，但实际模型经常违反。演示项目不能依赖「模型会记得」，必须把题面、附件、学生已答步骤做成显式会话状态。

### 3.4 数学推导

- **正确案例**：
  - A：e=2√2（S1/S2；封存基准 D）。
  - C：P(X=1)=5/125=1/25、5³=125（`C-t08-after.png`，run-03 SSE 一致）。
  - B：BC⊥平面 AA₁D 的判定（S7；封存基准 B）。
- **错误/风险案例**：
  - C 收束轮把 X 当「抽到的号码」（S4），与封存基准冲突。
  - A 收束轮题设比例复述反复（S6），虽结论对但过程不可用。
  - A 题把「求离心率比值」误判为「缺定大小条件」（S2 末尾、conv-8e006e4c、run-03 A t1）。
  - 判定器：学生正确的 BC⊥AA₁ 因目标式抽取 `AA_1D` 被判错（run-03 B）；A-t06 中 `c²=a²+b²` 被判 wrong 且 `p_before=p_after=1.0`（run-03 SSE）。
- **结论**：真实模型在高中标准题上的**结论正确率不低**，但「过程复述、条件识别、判定器」不可靠；任何用于演示的模型回答都必须经过数学审核与状态校验。

### 3.5 教学引导

- **好的引导**：
  - S3：首轮把注意力引到 B 选项，问「哪条直线可能垂直」。
  - S5：准确诊断「有放回/无放回」，提示「第一次/第二次/第三次」。
  - S7：用定理符号对照学生推理，指出「相交」条件不能丢。
  - C-t08：先讲清 X=1 的含义，再让学生自述理由。
- **坏的教学行为**：
  - 一次问多个问题（S3、S4、B card-1、A-t04、C-t05）。
  - 学生未作答就给完整解答（S2；A card-1；run-02 A t1 首轮）。
  - 同一问题重复问（run-01 A t6/t9；conv-722f0537）。
  - 补课知识点错配（A 题圆锥曲线→集合/三角函数）。
  - 错答追问插入无关历史错题（A-D3/C-D3）。
  - 「你连续三次都写同一个式子」这类带责备感的文案（run-03 B/C）。
- **结论**：真实模型能产生高质量教学语句，但**不能自主保持教学纪律**；演示项目需要把「一次一问、先让学生试、错因针对性、补课前置匹配」做成状态机/模板约束。

### 3.6 工具输出与过程呈现

- SSE 事件统计（27 份 `run-03/guide/api/raw/*.sse.txt`）：`token` 509、`meta` 27、`done` 25、`card` 41、`status` 15、`file_parsed` 3、`figure` 2、`citation` 1、`badge` 1、`title` 1。

- **局限**：没有独立「工具调用轨迹」面板；不能从画面确认 SymPy/TIR/检索是否真的执行；`citation` 只有 1 次事件，引用 chip 多数来自回答末尾的静态列表，未必逐条对应检索结果。

### 3.7 数学可视化

- 实时：`run-02/student/shots/a-t1-reply6.png` 的步骤卡含「可拖动 / ▶ 演示」图块；`run-03` SSE 有 2 次 `figure` 事件；`run-01 B/04-turn-01.png` 有三维正三棱柱图。

  - 但「可拖动/演示」主要是 UI 标签；没有拖动前后数值变化、帧切换、自动播放的实际记录。演示项目若要做交互图形，必须绑定真实计算/状态，不能只放图。
  - 图形帧是预生成 SVG data URI，体量大、不可参数化；在离线演示中可复用，但不能声称是实时计算。

**关键判断：**

1. **真实模型的高质量句子值得吸收，但不能原样播放。** 最明显的差距不是「模型不会说人话」，而是「模型不会稳定遵守教学纪律」。V5/V6/演示脚本的稳定度是用状态机换来的；代价是脚本感。
2. **人工脚本的最大风险不是内容差，而是「所有输入都通向同一节点」。** V5 的分支表把「为什么是2」「为什么是 C」「直接讲解」都映射到固定回复；演示 transcripts 也类似。成熟智能体产品的自然感来自「回答确实由当前上下文生成」，而不仅是文案写得好。
3. **最佳组合**：真实模型语料（经数学审核）作为「内容骨架」；状态机只负责「下一步该问什么/该给什么卡」；判定器/计算用真实本地逻辑；所有卡片状态来自真实会话，不预演未发生步骤。这与 V5 的「教学法在代码层、生成层只填文本」方向一致，但需要补上「真实上下文状态」。

## 6. 结论

1. **真实模型回答的最大价值是「自然语言与真实推导」，不是「流程可靠性」。** 本批样本中，S1/S2/S5/S7 的语句与推导可用于内容资产；S4/S6 及 A/B 丢题/循环证明真实模型会在题面、数学、判定上出错。
2. **真实模型的长度/结构有自然变化，但长答结构趋同。** 32–197 tokens、108–1091 字的跨度是真实的，但「复述 + 分步 + 结论 + 追问 + 难度行」几乎成了固定模板；演示项目应按教学阶段设计形态，而不是简单随机化。
3. **上下文承接在单 skill 内可工作，跨路由/门禁会断。** 演示项目必须显式保存题面、附件、已答步骤与判定结果；不能依赖模型记忆。
4. **工具结果应以教学卡呈现，而不是后台日志。** 原项目 SSE 的 `card/error_analysis/hint/progress/figure/citation` 是正确方向；但卡片内容必须与真实判定/检索绑定。
5. **人工脚本与真实模型各有所长。** 演示项目应采用「真实语料 + 状态机约束 + 本地计算」的混合方案；禁止把预置脚本宣称为实时模型，也禁止把真实模型的失败/降级当作「真实感」。
6. **所有候选内容必须过三关：** 数学正确性（对照封存基准）、上下文一致性（引用学生上一轮/题面）、教学纪律（一次一问、不泄底、错因针对）。未过三关的内容只能作为研究证据，不能进入演示。
