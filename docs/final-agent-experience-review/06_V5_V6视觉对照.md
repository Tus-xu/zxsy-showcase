## 0. 结论摘要

1. **当前演示（release/开始演示.html）是唯一具备真实产品外壳的版本**：首页、会话分组、置顶、搜索、历史恢复、错题列表、学情入口都在；这些是 V5/V6 完全没有的能力。但它也是三版中数学回答最“平”的：完整解析是一段连续文字 + 行内公式 + 一张小卡，练习答错后立即公布答案并自动跳下一题，错题详情在离线状态直接显示“详情加载失败”。这些不是视觉小瑕疵，而是现场演示会暴露的产品问题。
2. **V5 的核心价值是“把数学回答组织成可读的结构”**：展示公式、两列符号表、结论先行、同题重试、真实可拖动的 Canvas 图形。代价是它没有首页、没有历史会话、没有自由输入，练习与错题都很薄；侧栏直接写“示例会话”，明示自己是原型。
3. **V6 在 V5 基础上把数学可视化又推进一步**：彩色符号表、极大/极小值区间着色、只观察 x=−1 附近的局部图、结论 callout 都明显提升教学可读性。但 V6 的长回答更像“设计好的讲解页”，首屏即出现“回到最新”，关键结论在 1440×900 下落到输入框以下；“复制讲解”几乎出现在每条消息下，视觉噪声增加。
4. **版本越新不等于体验越好**：V6 的图形与图解应保留，V5 的简洁回答节奏与当前演示的历史会话/真实错题数据应保留；当前演示的练习立即公布答案、错题详情离线失败、图形被输入框遮挡必须修复，不能因为“当前是发行版”就默认它最好。
5. **V5/V6 不能作为“产品能力已存在”的证据**：它们是本地单文件原型，所有回答来自预置节点/分支，没有真实模型、没有后端、没有跨会话历史；本报告只把它们作为设计对照，不把它们的能力写成智学数研已经具备的能力。

## 2. 分场景对照

### 2.1 首屏与信息架构

**观察到的事实**

- 原项目历史首页（`qa/parity-r02/shots/live-student-dialog.png`，1672×941，历史采证）包含：个性化问候“夜深了，小林”、四张彩色入口卡、底部 5 条建议 chips、“学情脉搏 BKT·FSRS”面板（掌握度 2%、13 天连击、薄弱点、FSRS 复习队列）、置顶/今天/7 天内/30 天内会话分组。信息密度高，但它是 2026-11-21/22 的历史版本，不能描述为当前版本。
- 当前演示首页（`current/1440/home-01-top.png`）保留四入口、最近学习、学习进度卡、会话列表；入口改为白底描边卡；建议 chips 收进“提问建议”按钮，点击后才出现三条（`home-02-suggestions.png`）；“学情脉搏 BKT·FSRS”被简化为“学习进度 2%”。
- V5/V6 没有独立首页：打开即进入 `photo` 场景（`v5/1440/home-01-default.png`、`v6/1440/home-01-default.png`）。侧栏“首页”按钮实际执行 `switchScene('photo')`（V5 `resources/prototype/preview.js` 第 571 行 `const product = { home: 'photo', practice: 'variants', error: 'error' }`），并不是学习首页。V5/V6 侧栏标题分别是“示例会话”“学习会话”，只有 8 个固定场景，没有时间、分组、新建入口。
- V6 默认进入时，首条回答已经长于视口，首屏底部被输入框截断，并出现“回到最新”（`v6/1440/home-01-default.png`）；V5 同样内容较短，首屏完整（`v5/1440/home-01-default.png`）。

**判断**

- 当前演示是唯一具备“产品首页 + 真实历史会话”的版本；这是相对 V5/V6 的结构性优势，不能为了采用 V5/V6 的视觉而丢掉。
- 当前演示相比原项目历史版发生了信息密度退化：彩色入口卡、建议 chips、BKT/FSRS 解释被简化；这不一定都是坏事（更干净），但“学习进度”只剩一个 2% 数字，解释性下降。最终基线应决定保留哪一层，而不是简单回到历史版。
- V5/V6 的“无首页 + 场景列表”不是可交付的学生端信息架构；它们适合做“AI 回答设计实验台”，不适合作为最终演示外壳。

**值得保留/恢复**

- 保留：当前演示的首页骨架、会话分组、置顶/搜索、学习进度卡。
- 可恢复：原项目历史版的建议 chips 即时可见（不必全部展开）、BKT/FSRS 的简短解释（避免只剩数字）、彩色入口卡的一点色彩层次。
- 不应采用：V5/V6 的“首页 = 拍照场景”映射，以及把 8 个场景当作产品导航。

### 2.2 完整数学解析

**观察到的事实**

- 当前演示 `sc-s1`（`current/1440/photo-01-top.png`、`photo-02-bottom.png`）：题图卡、用户气泡、一段连续回答；四个加粗小标题（“找候选点”“看左右符号”“判极值并代回原式”“回扣你的问题”）承担结构；公式全部为行内，只有一张“看图解释”小卡（`photo-04-figure.png` 是展开后的图形）。整段回答没有展示公式、符号表、结论 callout。
- V5 `photo` 完整解析（`v5/1440/solution-02-middle.png`、`solution-03-bottom.png`）：展示公式 `g'(x)=6(x+1)(x−2)`、两列对比表（−1/2 的左右走势）、结论“局部极小值在 x=2 处取得，选 C”；操作按钮“试着独立判断 / ‘局部’具体是什么意思？”。回答被组织成一个有边界的“解释卡”，信息层级清楚。
- V6 `photo` 完整解析（`v6/1440/solution-02-middle.png`、`solution-03-bottom.png`）：开头是“从导数找到候选点”标题 + 大块展示公式；随后“数学图解 导数符号 → 曲线走势”彩色表（绿 + / 橙 − / 绿 +，递增/递减）；“2. 区分极值点与极值”展示 `g(−1)=8`、`g(2)=−19`；“最后结论”callout；补充“这道题没有实数域上的全局最小值”。视觉层级最丰富，但 1440×900 下“最后结论”落在输入框下方，必须滚动才能看到。
- 原项目历史真实回复（`evidence/live/run-02/student/shots/cap-A-02-reply1.png`，双曲线题）：有“线路有点波动，已切换备用通道，马上好… 2 条过程”的过程状态、AI 生成提示、编号步骤、自然承接“我看你之前做错过哦”；文本为主，没有展示公式块。题目不同，不能逐项比较数学内容，但它提供了“真实模型回复的自然语言与过程状态”参照。
- 另一条历史引导回复（`evidence/live/run-03/guide/shots/A-t05-after.png`）：以“你现在想一想…你还记得它是什么样的吗？”结束，并出现可输入式子面板；真实模型倾向于以问题收束，而不是一次给结论。

**判断**

- 当前演示的解析是“静态讲义感”的主要来源：不是文字不专业，而是所有数学信息都被压进同一段文字流，缺少展示公式、表格、结论卡这些“可扫描”的结构。
- V5/V6 的结构化明显提升了数学可读性；V6 的彩色符号表与结论 callout 是实质改善，不是装饰。
- 但 V6 也有反向风险：回答越来越像独立设计好的讲解页，长、完整、每步都展开，读者失去“在对话中逐步获得信息”的节奏；并非所有问题都需要这么多层。
- 原项目历史真实回复的“过程状态 + 编号步骤 + 自然承接”是当前演示缺少的：当前回答没有过程状态，也没有对上一轮的显式承接（只有预置的用户消息）。

**建议方向（供最终基线参考）**

- 采用“分层回答”：短问题用短回答；复杂解析只在关键步骤使用展示公式、符号表/结论卡，不强制每条回答都套完整模板。
- 保留当前回答的“自然语言讲解”语气，但把关键公式（如 `g'(x)=6(x+1)(x−2)`、`g(−1)=8`、`g(2)=−19`）提升为展示块；把“选 C”做成明确的结论卡。
- V6 的“数学图解”只在该图能解释当前疑问时出现（如符号表、局部邻域），不要为视觉丰富度强行插入。
- 原项目真实回复中的过程状态可以作为“离线回放说明”或“历史采证”展示，但不能伪造实时工具执行。

### 2.3 引导与纠错

**观察到的事实**

- 原项目历史真实引导（`evidence/live/run-03/guide/shots/A-t05-after.png`，双曲线题）：题目输入使用“符号键盘 + 表达式输入”（`c 2 a ^ 2 ...`），顶部有“第 2 步 / 共 3 步 · 引导中 · 提示档 开放追问”，知识点标签“圆锥曲线”；另一张（`B-t04-click.png`）显示“拆解思路 把关键空补上——每空从面板点选”“改写打字”“直接开始做”“跳过”等多种操作。原项目的引导是“写式子/填空”，不是四选一。
- 当前演示 `sc-s5`（`guide-01-initial.png`）：预置学生首答 A；助手先肯定“−1 确实让导数为零”，再进入“先读清这道题”卡；两个按钮“题目看懂了 / ‘局部’是什么意思？”。随后 `guide-02-method.png` 出现“你想先从哪一种方法试？”两张方法卡；`guide-03-values.png` 问“若 g(x)−g(a)>0 … 那么 g(a) 比这些值大还是小？”，提供两个整行按钮。顶部只有“分步推导”徽标，没有“第 x 步 / 共 y 步”。
- 当前演示超范围输入（`current/1440/unsupported-input.png`）：输入“黎曼曲率张量怎么计算？”后，助手回“这次提问没有预设讲解。你可以先选一个步骤，继续这道题。”然后重复展示“先读清这道题”卡，没有自然的能力边界说明。
- V5 `guide`（`guide-01-initial.png`、`guide-02-wrong.png`、`guide-03-repaired.png`）：四选一；选错 A 后助手解释“−1 的确让导数等于零…走过这个点时先上升再下降”，给出“卡住的是判据”note，再问“峰顶还是谷底”；订正后出现“已订正 / 首答 A·−1 → 最近作答 C·2 / 错答落在另一个导数零点…”记录卡，以及“加入错题本/到错题本查看/用变式试一遍”。选项点击记录为“本步作答 · A · −1”内嵌条。
- V6 `guide`（`guide-02-wrong.png`、`guide-03-repaired.png`）：同样四选一与同题重试，但增加“只观察 x=−1 附近”彩色数学图解（g′>0 绿色、g′<0 橙色、向右上升/下降），把“局部”判断可视化；订正后“C · 2”作为独立右侧用户气泡，而不是内嵌条。
- V5/V6 超范围输入（`v5/1440/unsupported-input.png`）：输入框上方出现低对比提示“这一句超出本场景的预设范围。可以换个问法，或用当前回复里的操作继续。”，输入内容保留在输入框。

**判断**

- 当前演示、V5、V6 都发生了“引导交互退化”：原项目历史版允许写表达式/填空/改写/跳过，三版都退化为选项按钮。这是能力退化，不只是视觉差异。
- V5/V6 的同题重试、明确错因、订正记录优于当前演示；当前演示的“分步推导”虽然自然，但没有步骤进度，学生不知道自己在哪一步，也没有像原项目那样的“提示档/开放追问”状态。
- V6 的局部彩色图解是本次对照中最有价值的教学可视化之一，值得保留。
- 选项点击是否要生成用户气泡需要明确规则：V5 的内嵌条更像“组件状态”，V6 的独立气泡更像“对话发言”。按 task §10.5，展开/收起/切换图形等界面操作不应生成气泡；答题是否属于“对话发言”应由产品定义，并保持三版一致。
- 超范围输入的处理目前都不自然：当前演示重复展示同一张读题卡；V5/V6 只有输入框上方的小字提示，容易被忽略。需要明确的“能做什么/不能做什么”边界说明，而不是随机匹配或重复卡片。

**建议方向**

- 至少为关键步骤恢复“表达式输入/填空/改写”能力，或提供“点选 + 打字”双通道；不能所有步骤都是四选一。
- 增加“第 x 步 / 共 y 步”进度、当前知识点、提示档位（如“先提示/给步骤/看答案”）。
- 保留 V5/V6 的同题重试与订正记录；保留 V6 的局部邻域图。
- 明确“组件操作 vs 对话消息”的规则，并在 UI 上区分。

### 2.4 动态图形

**观察到的事实**

- 当前演示 `sc-s3`（`graph-02-frame.png`）：图形是预渲染图片帧，控件只有“▶ 演示/重播”和三帧点（整条曲线→聚焦(−1,2)→聚焦(1,−2)）；不能拖动参数。图形在 1440×900 下被输入框截断，底部图例/控制不可见；`graph-01-initial.png` 也同样被截断。`graph-03-counter.png` 是“看看反例”后追加的卡片。
- V5 `graph`（`graph-02-slider.png`）：Canvas 曲线 + 虚线切线 + 可拖动滑块 `a` + 4 个预设点（−1.4 / −1 / −0.6 / 1）；读数“a=-1.4 / 点(-1.4,≈1.46) / 切线斜率 2.88”。图形完整可见，交互为真实本地计算。
- V6 `graph`（`graph-02-slider.png`）：同 V5 的滑块，但增加绿色/橙色增减区间、极大值点/极小值点标注、三块读数卡（a、点、切线斜率）。`graph-03-flat.png` 用同一组件展示 `f(x)=x³` 反例，原点切线水平、斜率 0，两侧同号。
- Desmos 竞品（`evidence/market-competitors/math/desmos-03-extrema-points.png`，官方产品实机、其他研究代理采集）：表达式列表 + 曲线 + 可标注极值点 (−1,2)/(1,−2)；用户可直接编辑函数、添加点、拖动滑块。它不是聊天产品，仅作图形交互参考。
- 原项目历史：未找到对话内动态图形实机截图。只在 `evidence/live/run-02/student/shots/s04-errors.png` 的错题详情看到“生成动态图形（可拖动/旋转/缩放）”按钮文案；没有实际图形画面，**未验证**当时是否真实可操作。

**判断**

- 当前演示的“动态图形”本质是图片帧播放，不满足 task §10.4“切点移动后，函数值与导数值真实变化”；且被输入框截断，现场演示会直接暴露。
- V5/V6 的 Canvas 图形是真实本地计算 + 参数交互，图形完整；V6 的增减色块与极值标签显著提升教学可读性，是应保留的方向。
- Desmos 说明图形可以作为可编辑、可标注、可直接操作的对象；V5/V6 仍只支持单参数滑块与预设函数，尚未达到“通用数学实验”程度，但作为对话内组件已经足够。
- 原项目“可拖动/旋转/缩放”的按钮只是文案，不能据此认定原项目已实现；不能把文案当实机证据。

**建议方向**

- 采用 V6 的 Canvas 图形组件（或等价实现），保证图形完整位于可视区、控制可见、读数与数学量真实联动。
- 图形出现时不要遮挡输入框；可以在图形下方预留操作区，或让图形高度自适应视口。
- 若保留“播放帧”模式，应明确它是“分步聚焦”，不要把它包装成“可拖动图形”。

### 2.5 练习

**观察到的事实**

- 当前演示 `sc-s4`（`practice-02-wrong.png`）：学生选 A（−1）后，页面立即显示“答案：C”，解析“你找到了候选点…错选 A 是把局部极大当成了极小”；随后自动出现“变式 2/3 改变函数走势”新题及四个选项。学生没有第二次尝试机会，也没有明确的“看解析/继续”选择。
- V5 `variants`（`practice-02-wrong.png`、`practice-03-correct.png`）：选 A（−2）后，助手指出“−2 的确是零点，但 3(x²−4) 在它左边是正，右边是负…再选一次。”并保留 A/B/C 三个选项；学生选 B 后才进入下一题。解析不提前公布答案。
- V6 `variants`（`practice-02-wrong.png`、`practice-03-correct.png`）：同 V5 的重试逻辑；答案以独立用户气泡“A · −2”呈现；答对后“下一题”按钮才出现。
- 原项目历史练习页（`evidence/live/run-02/student/shots/s03-practice.png`，1672×941，历史采证）：“今日训练 · 5 题导数的概念与运算”独立页面，按 3:2:1 难度配比、预计掌握度 0%→15%；不是对话内变式，不能直接与三版对比。

**判断**

- 当前演示的练习反馈是本次对照中最严重的产品问题之一：答错即公布答案并自动跳题，既不自然，也违背教学规律；学生没有“我再试一次”的机会。
- V5/V6 的同题重试、保留选项、答对后再下一题，明显更符合对话式教学。
- 当前演示的“答案：C”与解析文字本身是正确的，但呈现方式像考试答案解析，而不是导师反馈；需要改成“提示→再试→解析”的分层反馈。

**建议方向**

- 答错后不直接显示最终答案；先给错因提示，再让学生重试；只有学生主动点“看解析”或连续两次错误后才展示完整解析。
- 下一题必须由学生点击“继续/下一题”触发，不能自动推进。
- 保留 V5/V6 的“同题重试 + 答对后下一题”节奏，同时保留当前演示的题库/变式结构。

### 2.6 错题

**观察到的事实**

- 当前演示 `#/errors`（`error-03-errors-page.png`）：页面进入后自动打开“错题详情 · 第 01 题”弹窗，弹窗内容为“详情加载失败：离线体验暂未提供这项内容。”；背景列表仍显示 26 道错题，顶部能看到刚从 `sc-s6` 加入的 `g(x)=2x³−3x²−12x+1` 条目（`error-02-added.png` 为加入后的会话卡）。这是离线发行版的真实失败，不是设计占位。
- V5 `error`（`error-00-empty.png`、`error-01-notebook.png`）：空态“这里还没有保存的错题 / 打开引导与订正”；完成引导并加入错题本后，显示一条记录：“已知 g(x)=2x³−3x²−12x+1… 已订正 首答 A·−1 → 最近作答 C·2 / 错答落在另一个导数零点… / 已保存在此浏览器 · 原题与首答随记录保留”。内容真实可追溯，但没有复习排期、错因诊断、重做入口。
- V6 `error`（`error-00-empty.png`、`error-01-notebook.png`）：同 V5，记录卡为浅绿 review 面板，视觉更清楚；但“复制讲解”出现在错题记录下方，语义略怪；仍无 FSRS/复习排期/重做。
- 原项目历史错题详情（`evidence/live/run-02/student/shots/s04-errors.png`，1672×2164，历史采证）：弹窗包含原题、正解、AI 问诊·错因、记忆状态（FSRS：遗忘风险/当前记得概率/记忆等级）、隐藏答案重做、引导重解、AI 答疑；信息完整。它是历史版本，不能描述为当前版本效果，但说明原项目曾经具备更完整的错题诊断能力。

**判断**

- 当前演示错题详情离线失败是发行版高风险缺陷：现场演示一旦点开错题就会看到“加载失败”，直接破坏可信度。必须修复或在离线演示中隐藏自动弹窗，并给出可信的替代内容。
- V5/V6 的错题本只保存“本次预览中实际提交并加入”的记录，数量 1 条；它能证明“作答记录真实可追溯”，但不能证明错题管理能力。
- 原项目历史版的 AI 问诊/FSRS 是内容深度参照；当前演示与 V5/V6 都发生了内容退化（V5/V6 作为原型可理解，当前演示作为发行版不可接受）。

**建议方向**

- 当前演示：为错题详情补齐离线数据（题干、正解、错因、来源、复习状态），或至少做“离线演示版：展示已缓存详情”的完整内容；禁止出现“加载失败”。
- 若保留 V5/V6 的错题本，应明确它是“本次演示记录”，不要伪装成完整错题库；可增加错因、首答/订正、下次复习时间。
- 不要把原项目历史版的 FSRS 数字直接复制成当前能力；如需展示，必须用本地真实计算或明确标注为历史采证。

### 2.7 历史会话

**观察到的事实**

- 当前演示 `history-01-sidebar.png`：左侧会话列表有“置顶 / 今天 / 7 天内 / 30 天内”分组、时间戳、搜索框、新建按钮；点击“拍照解题 · 三次函数极值”后恢复完整对话（`history-02-reopen.png`）。这是真实历史会话，且与 `qa/parity-r02` 中历史版结构连续。
- V5 `history-01-switch.png`：侧栏“示例会话”只有 8 个固定场景；没有时间、分组、新建；点击场景只是切换预设 run；`history-02-reload.png` 显示刷新后恢复当前场景的 localStorage 状态。`preview.js` 中 `storageKey = 'zhixueshuyan-v5-design-preview'`，保存的是 `runs`/`notebook`，不是会话列表。
- V6 `history-01-switch.png`：同 V5，侧栏“学习会话”仍是固定场景切换器；没有按时间保存的对话历史。

**判断**

- 当前演示的历史会话是相对 V5/V6 的结构性优势，也是产品真实感的重要来源；不能因为 V5/V6 的视觉更漂亮就放弃。
- V5/V6 的“场景切换 + localStorage 恢复”不是历史会话；它只能证明“同一场景刷新可恢复”，不能证明“多轮会话可回看”。如果最终采用 V5/V6 外壳，必须补真实历史列表。
- 历史版与当前演示的分组结构连续，这是原产品继承中值得保留的部分。

**建议方向**

- 保留当前演示的会话列表、分组、置顶、搜索与恢复逻辑。
- 如果最终采用 V5/V6 的视觉，必须为其补上真实会话列表（按时间、按场景、按学习主题），不要把“示例会话”改名为“历史会话”了事。
- V5/V6 的“场景”可作为“示例库/课程包”，与真实历史会话分开呈现。

### 2.8 1920 大屏

**观察到的事实**

- 当前演示 1920：`current/1920/home-01-top.png`、`photo-02-bottom.png`、`guide-03-values.png`。正文列宽约 860px，右侧留白明显；解析仍为连续文本；引导按钮仍为窄行。
- V5 1920：`v5/1920/home-01-default.png`、`solution-02-middle.png`、`guide-02-wrong.png`。内容列约 850px，未随视口扩展；公式/表格清晰，右侧大留白。
- V6 1920：`v6/1920/home-01-default.png`、`solution-02-middle.png`、`guide-02-wrong.png`。数学图解在 1920 下最完整；但内容列仍约 850px，底部仍可能被输入框截断。
- 历史 1920：未找到原项目 1920×1080 实机截图，**证据不足**，未做跨尺寸像素对照。

**判断**

- 三版都没有把阅读列扩展到与 1920 屏幕相称的宽度；大屏现场会出现大量空白。对于“现场演示”而言，这既可能是留白美学，也可能是信息不足，需要结合投影距离决定。
- V6 的彩色图解在 1920 下最完整，说明该组件适合大屏；当前演示的静态图帧在大屏下仍被输入框截断，问题不会因屏幕变大而消失。

**建议方向**

- 在大屏下可适度放宽阅读列（如 960–1080px），或利用右侧空白放“学习状态/知识点/下一步建议”等辅助信息，而不是无意义留白。
- 图形/表格组件应有最大高度与滚动策略，保证不被输入框遮挡。

### 3.3 回答同质化

- **当前演示**：所有助手消息共用同一种无边框文本流；长短回答的差异主要靠文字数量，而不是形态（`current/1440/knowledge-02-bottom.png` 与 `photo-02-bottom.png` 对比：短回答与长回答的容器/层级几乎一样）。
- **V5/V6**：所有助手消息共用同一种圆角面板；V6 连一行短答也套完整面板 + “复制讲解”（`v6/1440/knowledge-04-short.png`），长答与短答的边界差异不足。V6 的“讲解页”形态更强化了“每条回复都是设计好的页面”的感觉。
- **建议**：至少区分“短问答/概念解释/完整解题/引导追问/练习反馈/错题记录”六种形态；统一字体、色彩、间距，不要统一所有容器形状。task §9.2 明确反对“所有 AI 回复必须有/无边框”的预先限制。

### 3.4 数学表达问题

- 当前演示的关键公式全部行内，长公式在文本流中换行，阅读时难以定位（`current/1440/photo-02-bottom.png`）。
- V5/V6 的展示公式、表格、符号表更清楚；但 V6 的来源弹窗仍显示“**V5 自编讲义 · 导数与极值**”（`v6/1440/knowledge-03-source.png`），V6 包内出现 V5 命名，属于内容卫生问题。
- V5/V6 的图形使用 `f(x)=x³−3x` 与 `f(x)=x³`，与拍照题 `g(x)=2x³−3x²−12x+1` 是不同函数；它们在回答中明确说明“这个图和拍照题用的是两个不同函数”（V5 data `graph-sign` 节点），这是诚实的，但连续学习时可能造成混淆；需要在教学主线中说明“迁移的是方法，不是同一题”。

### 3.5 产品割裂感与不自然流程痕迹

- V5/V6 侧栏“示例会话/学习会话”与“首页→拍照解题”的映射，让产品看起来像“设计实验台”，不是学生端（`v5/1440/home-01-default.png`、`v6/1440/home-01-default.png`）。
- V6 初始加载就出现“回到最新”，说明滚动位置/内容高度管理不自然（`v6/1440/home-01-default.png`）。
- 当前演示的“回到最新”在回答中部悬浮（`current/1440/photo-01-top.png`），遮挡正文；`graph-02-frame.png` 中遮挡图形。
- 当前演示引导预置“我选 A”的首答（`current/1440/guide-01-initial.png`），学生进入会话时并未实际作答；这属于“未作答却已有学生答案”的演示痕迹。V5/V6 也用 `seed` 预置学生发言，但侧栏明确“示例会话”，语义上更可接受；当前演示是产品外壳，需要在 UI 上标明“示例会话/历史回放”，否则会被误认为学生刚刚作答。
- V5/V6 的选项点击变成“本步作答”条（V5）或用户气泡（V6），两者的语义不一致；最终基线需要统一规则。

### 3.6 值得恢复的历史设计

1. **表达式输入 + 符号键盘 + 填空/改写/跳过**（`evidence/live/run-03/guide/shots/A-t05-after.png`、`B-t04-click.png`）：原项目真实引导的核心交互，当前/V5/V6 全部丢失。
2. **步骤进度与提示档**（同上“第 2 步 / 共 3 步 · 引导中 · 提示档 开放追问”）：当前/V5/V6 都没有。
3. **错题详情中的 AI 问诊/FSRS/重做/引导重解**（`evidence/live/run-02/student/shots/s04-errors.png`）：原项目历史版有，当前演示退化为加载失败；应至少恢复离线可用的简化版。
4. **建议 chips 的即时可见性**（`qa/parity-r02/shots/live-student-dialog.png`）：当前演示收进“提问建议”，可考虑恢复为一行 2–3 条。
5. **彩色入口卡与学情解释**：历史版的色彩与 BKT/FSRS 解释可局部恢复，但不要恢复过多后台指标。

### 3.7 值得保留的新版设计

1. V6 的局部邻域图、彩色符号表、图形增减区/极值标签（`v6/1440/guide-02-wrong.png`、`graph-02-slider.png`）。
2. V5 的两列符号表与结论先行（`v5/1440/solution-02-middle.png`）；比 V6 更克制，适合中等长度回答。
3. 当前演示的真实历史会话、首页骨架、错题列表、来源片段展开（`current/1440/history-01-sidebar.png`、`home-01-top.png`、`knowledge-03-source.png`）。
4. V5/V6 的同题重试与“已订正”记录卡（`v5/1440/practice-02-wrong.png`、`guide-03-repaired.png`）。

### 3.8 不应继续的设计

1. 把图片帧播放当成“动态图形”。
2. 所有回答套同一模板/同一面板，尤其 V6 每条消息都带“复制讲解”。
3. 答错立即公布答案并自动跳题。
4. 用“示例会话”列表冒充历史会话。
5. 用预置首答/预置订正制造“学生已完成”的假象，而不标注示例/回放。
6. 离线发行版出现“加载失败”的错题详情。

## 4. 比较限制与证据边界

1. **视口/时间/数据不同**：原项目历史截图为 1672×941（2026-11-21/22），当前/V5/V6 为本轮 1440×900 与 1920×1080（2026-11-25）；时间、字体渲染、滚动位置、数据均不同。禁止做像素级结论。
2. **历史图不是当前版本**：`qa/parity-r02` 的 “live-*” 是原真实项目历史采证，`evidence/live/run-02/03` 是历史真实运行记录；不能把它们描述成当前版本效果，也不能把其中的能力当成当前演示已具备。
3. **V5/V6 是原型，不是产品**：所有回答来自预置节点/分支（V5 `resources/prototype/data.js`；V6 单文件内嵌数据）；没有真实模型、没有后端、没有跨会话历史；V5/V6 的视觉完成度不等于能力完成度。
4. **数学题目不同**：原项目历史回复是双曲线离心率；当前拍照题是 `f(x)=x³−3x`；V5/V6 拍照题是 `g(x)=2x³−3x²−12x+1`。只有引导/纠错板（当前 `sc-s5` 与 V5/V6 `guide`）是同一道 `g(x)` 题，可严格对比引导文案与交互；其余是形态对照。
5. **动态图形历史证据不足**：没有原项目对话内动态图形实机截图；只有错题页按钮文案，不能据此判断原项目真实能力。本报告将该项标为“未验证”。
6. **竞品 Desmos 不是聊天产品**：它只能证明“数学图形可以作为可编辑/可标注对象”，不能证明聊天产品应如何组织对话、工具状态或回答边界；Desmos 截图由其他研究代理采集（`notes/desmos-run.json`），不是本代理操作。
7. **V5/V6 的“历史会话”不是历史**：只是固定场景 + localStorage 恢复；不能与当前演示的会话列表做功能等同比较。
8. **未验证项**：原项目真实动态图形是否可拖动/旋转/缩放；原项目当前版本的错题详情是否仍保留 FSRS/AI 问诊；V5/V6 在真实模型接入后的回答长度/分支行为；当前演示在真实设备投影下的可读性。

## 5. 对最终改造的输入（不直接实施）

**建议采用**

- 当前演示的产品外壳：首页、会话分组、历史恢复、错题列表、来源片段。
- V6 的数学可视化组件：局部邻域图、彩色符号表、图形增减区/极值标签；但只在能解释当前疑问时出现。
- V5 的“结论先行 + 两列符号表”作为中等长度解析的模板；V6 的全套讲解页只用于“完整解析”场景。
- V5/V6 的同题重试、错因提示、订正记录；把“下一题”改为学生主动触发。
- 原项目历史的表达式输入/填空/改写/跳过、步骤进度、提示档，作为引导交互的目标形态（可在离线范围内实现为本地判定）。

**建议避免**

- 把 V5/V6 的场景列表当历史会话；把 V5/V6 的“首页=拍照”当信息架构。
- 让所有回答使用同一容器/同一“复制讲解”。
- 用静态图片帧冒充动态图形；用预置分支冒充真实模型。
- 在离线发行版暴露“加载失败”的错题详情。
