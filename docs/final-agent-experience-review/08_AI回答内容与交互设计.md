## 0. 结论摘要

1. **先定形态，再写文案。** 七类回答（微答 / 概念解释 / 完整解题 / 错误诊断 / 交互实验 / 练习 / 记录小结）按「意图 + 会话状态 + 内容需要」判定，不由节点编号或消息序号决定。微答不带卡，长答最多一图一表；禁止每条回复都走同一个 `progress + card` 骨架（09 §3.4、01 F1/F2）。
2. **主线剧本（新对话 + S1/S2/S5/S6）已写成可直接抄进 `engine.js` / `transcripts.js` 的完整中文**。每条 AI 回复都标注形态、长度、引用学生哪句话、下一步出口。
3. **接住学生的话**是每条回复的硬约束：至少引用一处学生原话/选择/式子；答错时只指出一处错步，只问一个可回答的问题；不重讲全题、不重复整张读题卡。
4. **分支矩阵覆盖 11 类输入**（答对 / 答错 / 求导错误 / 极值判断错误 / 自由追问 / 要求看图 / 要求提示 / 跳过步骤 / 不同表达 / 非预期输入 / 中断返回），给出关键词族、否定语义、回复策略与「是否生成用户消息」。
5. **能力边界必须具体到「能做什么、可点什么」**；「今天天气不错 → 重复读题卡」是明确的反面样板（历史 QA `21-V06-unrelated.png`）。
6. **数学逐条验算**：f(x)=x³−3x、g(x)=2x³−3x²−12x+1、h(x)、q(x)、r(x)、y=x² 的导数/零点/符号/极值全部用 SymPy 复核，脚本 `.work/agent-exp/scripts/s3/verify_math.py`，结果见 §5。
7. **落地只需要少量结构改动**：S1 追问问答节点、S5 符号提问节点、S6 动态记录种子、练习卡收尾文案核对、UI 操作不生成气泡。逐项列在 §7.3。

## 1. 回答形态分类（七类）与判定规则

### 1.1 七类形态表

> 长度按「中文字符 + 公式 + 标点」计；上限是硬约束，目标是常态。现有承载列指向当前工作树的组件/字段。

| 形态 | 何时用 | 长度上限 | 图 / 表 / 卡 | 结尾如何交给学生 | 现有承载 |
|---|---|---|---|---|---|
| **微答** | 单点事实、是非判断、一句纠偏、确认学生已做对、回答一个很小的「为什么」 | 1–3 句，≤90 字 | 不带卡；最多 1 个行内公式 | 一个可回答的问题，或 1–2 个自然语言出口（「那 −1 呢？」「来一道变式」） | `token` 纯文本；`MessageBubble` 正文；不需要 `showcase_stage` |
| **概念解释** | 问定义、区别、为什么、某个结论成立的条件 | 120–260 字 | 1 个展示公式；0–2 个引用 chip；不带交互卡 | 一个检验问题（「你能用 x³ 解释吗」）或一个反例邀请 | `token` 文本 + `citation`（`knowledge.refs`） |
| **完整解题** | 上传题图、明确要求「完整解答/把两个极值写出来」 | 300–700 字 | 1 个图（消息级 `figures`）；必要时 1 个符号表；不再叠练习卡 | 3 个出口：追问某一点 / 看图 / 来一道变式 | `token` 文本 + `figures`（`MathFigure`）+ 可选 `showcase_stage(derive, triples)` |
| **错误诊断** | 学生给出错误答案、错误步骤、错误理由 | 80–200 字 | 1 个 2–3 选项卡；0 图；不附完整解答 | 恰好一个可回答的问题（左/右符号、正/负、极大/极小） | `token` 文本 + `showcase_stage(derive, options)` |
| **交互实验** | 要求看图、看曲线怎么变、动手演示 | 40–120 字引导 | 1 个图/帧卡；数值来自本地 `plot.js`；组件操作不生成消息 | 「看完告诉我：经过 −1 时是升还是降？」+ 1–2 个出口 | `token` 文本 + `figures`（`MathFigure`，3 帧） |
| **练习** | 要求变式、巩固、出题；诊断后进入练习 | 30–100 字 | 1 个 `quiz_set` 题卡（1–3 题）；不附新讲解 | 「从第一题开始」/「做完告诉我」/「先不练」 | `quiz_set`（`quizChain()`），判分与 `quizLog` 为本地真实逻辑 |
| **记录 / 小结** | 完成引导、要求总结、错题复盘、保存错题 | 60–200 字，或 ≤6 条 bullet | 1 个 `summary` 或 `errorbook` 卡；只列实际发生的事件 | 回看 / 再练 / 保存（只有真实可保存时才给保存） | `showcase_stage(summary)`、`showcase_stage(errorbook)`、`cardSummary(summaryOf(s))` |

**形态不是容器。** 微答和概念解释都在同一条无边框正文里；完整解题只比它们多一个图；错误诊断多一个选项卡；练习和记录才使用独立组件。差异来自内容结构与组件是否必要，而不是「每条消息套一张卡」（01 §7.1、V6 文档 §1 的同质化诊断）。

### 1.2 判定顺序（D0–D7）

判定只看三件事：**学生这句话要什么**（意图）、**会话现在到哪一步**（状态）、**讲清楚需要什么材料**（内容）。不按节点编号选形态。

| 顺序 | 条件 | 形态 |
|---|---|---|
| D0 | 超出「导数与函数单调性 / 极值」范围，或要求联网/闲聊/代写作业 | **能力边界**（§4，不属于七类） |
| D1 | 消息本身是一个作答/步骤（选 A、x=2、左正右负、我算的导数是…） | 对 → **微答**；错 → **错误诊断** |
| D2 | 上传题图，或明确要求「完整解答 / 把过程写出来」 | **完整解题** |
| D3 | 问定义、区别、为什么、某个结论的条件（没有给出具体步骤） | **概念解释** |
| D4 | 要求看图、画图、播放、动手 | **交互实验** |
| D5 | 要求变式、练一练、出题、巩固 | **练习** |
| D6 | 问「我刚才做了什么 / 帮我总结 / 记下来 / 复盘」 | **记录 / 小结** |
| D7 | 其余（短追问、半句话、情绪表达） | **微答 + 一个澄清问题** |

**状态覆盖（优先于 D1–D7）：**

1. 学生上一轮已经答对同一件事 → 不再重讲；微答确认 + 下一步。
2. 学生重复同一个问题 → 微答换一种说法 + 指向上次给的结论；禁止逐字重复（07 §2 S8 的反例：同一句话得到几乎相同回答）。
3. 学生连续两次说「不会/没思路」 → 降一级提示（更具体），不贴「你怎么还不会」的标签（02 §5.3、07 §3.5）。
4. 学生要求「直接看答案/直接告诉我」 → 完整解题，但明说「这是完整解答」，不声称学生已经自己完成（13 一票否决第 12 条）。
5. 学生跳过步骤 → 记录里写「你跳过了这一步」，不写成「你完成了」。
6. 学生结论对但过程错 → 先肯定结论，再只指出过程里的一处问题；不要只判对/错（E-R5-07 的承接方式）。
7. 学生用不同表达 → 归一到同一判据；唯一命中就继续，歧义就问一个澄清问题，不重复整卡。
8. 学生中断后返回 → 从 `session` 恢复，引用最后确认的一步；不重新问候、不重新诊断。

### 1.3 不堆组件的硬规则

| 形态 | 最多组件 | 禁止 |
|---|---|---|
| 微答 | 0 卡 | 不要为了「看起来丰富」附符号表/图/练习 |
| 概念解释 | 1 个展示公式 + 2 个引用 | 不要附练习卡、不要附「学习目标」 |
| 完整解题 | 1 图 + 1 表 | 不要在同一轮再塞练习、总结、引用堆 |
| 错误诊断 | 1 个问题卡 | 不要附完整解答、不要一次问两个问题 |
| 交互实验 | 1 个图/帧卡 | 不要用装饰动效冒充计算 |
| 练习 | 1 个题卡 | 不要附新讲解；判分后才给反馈 |
| 记录 / 小结 | 1 个 summary/record 卡 | 不要配新图、新题、无关引用 |

> 依据：09 §3.4「每条 AI 回复几乎都是 progress + 卡片」是脚本感的主要来源；03b F2「工具活动低干扰」；任务书 §10.2「不要为了视觉丰富性强制每次插入图表、练习、总结和知识卡片」。

### 1.4 形态与「接住学生」的关系

- **微答**必须至少含一处学生原词/原选择（「你说的左正右负」「你选的 C」）。
- **概念解释**开头先回应学生的具体困惑（「你分不清切线和割线」），再给定义。
- **完整解题**第一句引用学生的困难（「你说『能求导，但不会判断单调区间』」），再说明卡在哪。
- **错误诊断**第一句引用学生原话（≤25 字），第二句只指出一处错步。
- **交互实验**说明「看什么」，不替学生看结论。
- **练习**回扣学生刚错的那一步（「还是同一顺序：先找候选点，再看两侧符号」）。
- **记录**只写实际发生的事件；没有记录就不生成。

#### 2.1.1 轮次 1（学生）


#### 2.1.2 轮次 2（AI-1 · 完整解题）

**【形态】** 完整解题｜**【长度】** 约 425 字（上限 700）｜**【引用】** 「我能求导，但不会判断单调区间」｜**【出口】** 「为什么 x=1 是极小？」/「给我一道变式」/「看看图」

```text
你说「能求导，但不会判断单调区间」——卡住的不是求导，是把「导数的正负」翻译成「函数的升降」。就按这道题走一遍。

f(x)=x³−3x，定义域是全体实数。求导：f′(x)=3x²−3=3(x+1)(x−1)。

令 f′(x)=0，得到两个候选点 x=−1 和 x=1。它们只说明切线水平，还不能说明是极大还是极小。

用这两个点把定义域分成三段，每段取一个数看导数的符号：在 (−∞,−1) 取 x=−2，f′(−2)=9>0；在 (−1,1) 取 x=0，f′(0)=−3<0；在 (1,∞) 取 x=2，f′(2)=9>0。

所以函数在 (−∞,−1) 上递增，在 (−1,1) 上递减，在 (1,∞) 上递增。在 x=−1，导数由正变负，函数先升后降，f(−1)=2 是局部极大值；在 x=1，导数由负变正，函数先降后升，f(1)=−2 是局部极小值。

回到你的问题：判断单调区间，就是看导数在每一段上的正负；候选点只是用来分段的位置。
```

```text

$$\frac{f(a+h)-f(a)}{h}$$

让 h 趋近 0（h≠0），如果这个比值趋近一个有限值，它就是 f′(a)，也就是 A 点切线的斜率。

```

| **首答正确** | `store.quizLog` 中 V1 首答即正确 | AI 确认 + 复盘正确顺序 | 记录 / 小结 |
| **没有记录** | 以上都不成立 | AI 空态说明 | 能力边界 + 空态 |

#### 2.4.2 有错答记录（逐字）

**【形态】** 记录 / 小结｜**【长度】** 约 86 字（有理由时）/ 约 63 字（无理由时）+ 1 个 `errorbook` 卡｜**【引用】** 记录中的首答 A / 订正 C（不是一句新的聊天原话；若学生先发了「帮我复盘」，开头引用这句）｜**【出口】** 「来一道换系数的题」/「回看当时的对话」/「记进错题本」

有理由时：

```text
这是你在这台设备上留下的记录：首答 A（x=−1），订正 C（x=2）。你当时的理由是「x=−1 能让导数等于零」，缺的一步是看 −1 两侧的符号：左正右负，所以它是极大。
```

没有理由字段时：

```text
这是你在这台设备上留下的记录：首答 A（x=−1），订正 C（x=2）。复盘只看两步：−1 为什么不是极小，2 为什么是极小。
```

如果记录只有首答 A、还没有订正，不要套上面的「订正 C」文案；用：

```text
你在这道题上选了 A（x=−1），还没有订正。先看 −1 两侧：左正右负，所以它是极大；极小在 2。要不要回题卡重选一次？
```

记录卡 `fixed` 写「未订正」，不要写 C（模板会渲染成「订正 未订正」，W3 可再加一个 `pending` 状态样式）。

**承载**：`showcase_stage(errorbook)`（`ShowcaseStageCard.vue:137-144`）：

```js
{
  type: 'showcase_stage',
  variant: 'errorbook',
  stage: '订正',
  title: '这次作答的记录',
  question: V1.question_text,
  options: V1.options,
  first: 'A',
  fixed: 'C',
  chosen: 'A',
  reason: '把局部极大当成了局部极小：只看导数等于零，没看两侧符号。',
  readonly: true,
  note: '记录来自你在这台设备上的实际作答。',
}
```

- `first/fixed/reason` 必须来自真实记录（`store.errorBook` / `store.showcase['sc-s5']` / `store.quizLog`），不能写死 A/C。
- `reason` 按首答选项映射：A → 「把局部极大当成了局部极小：只看导数等于零，没看两侧符号」；B → 「把 x=1 当成了候选点」；D → 「把 x=−2 当成了候选点」；首答正确 → 不生成错因卡。映射表放 `errorbook.js` 或 `session.js`，不要散落在文案里。
- 「记进错题本」按钮只在尚未保存时出现；保存后改成「已在错题本」状态，重复点击不新增（`errorbook.js:14-38` 的幂等设计保留）。
- 保存动作不生成学生气泡（§3.3）；当前组件仍会生成，需 M5。

#### 2.4.3 首答正确

**【形态】** 记录 / 小结｜**【长度】** 85 字｜**【引用】** 记录里的首答 C｜**【出口】** 「来一道换系数的题」/「回看当时的对话」

```text
这道题你首答就选对了 C（x=2），没有错因可复盘。可以回看这次做对的顺序：先找候选点，再看 2 两侧是左负右正，先降后升，所以是极小。要不要用同一顺序做一道换系数的题？
```

**承载**：`cardSummary` 或纯文本 + `quizChain()`（若学生接「来一道」）。不要生成 `errorbook` 卡，因为没有错因。

#### 2.4.4 没有记录（空态）

**【形态】** 能力边界 + 空态｜**【长度】** 98 字｜**【引用】** 无（不伪造学生发言）｜**【出口】** 「去引导式解题」/「回到左侧示例列表」

```text
这里还没有你的作答记录。错题复盘只根据你实际做过的题生成。你可以先去「引导式解题 · 为什么不是极小值」做一遍：先选一次，再看两侧符号。做错或订正之后，这里会出现你自己的记录。
```

**承载**：纯文本；无卡。不要用一个「去引导式解题」按钮生成一条用户气泡（当前 `showcase_stage` 的 action 会生成；M5 之前用纯文本 + 左侧导航）。

## 3. 分支矩阵

### 3.1 识别总则（关键词族 + 否定语义）

**关键词族**（用 `norm()` 去空白/标点后做包含判断；只扩意图族，不无限堆同义词）：

| 意图族 | 关键词 |
|---|---|
| 作答 | 选项字母 A/B/C/D、`x=`、`−1`、`2`、`左正右负`、`左负右正`、`正`、`负`、`极大`、`极小`、`对`、`是`、`嗯` |
| 求导 | 求导、导数、导函数、微分、`f′`、`g′`、`我算的导数是`、`求导错了` |
| 极值判断 | 极小、极大、极值、最小值、最大值、驻点、转弯、山谷、山顶、谷底、波峰 |
| 自由追问 | 为什么、怎么、那…呢、如果、是不是、能不能、还有、举个例子、什么意思 |
| 看图 | 图、画、曲线、图像、可视化、演示、动一下、长什么样、播放 |
| 提示 | 提示、怎么做、不会、不懂、没思路、卡住、帮帮我、从哪开始、给点方向 |
| 变式 | 变式、再来一道、练、出题、巩固、换个题、考考我 |
| 记录 | 记下来、错题、保存、总结、复盘、刚才做了什么、学习记录 |
| 中断 | 等一下、先停、我回来了、继续刚才、回到上一题、接着讲 |
| 否定 | 不、别、不用、不要、先不、算了、不是、没有、并没、不需要 |
| 不确定 | 不确定、不知道、不会、可能、大概、也许 |

**否定语义规则：**

1. 否定词修饰紧跟的意图词：`不用画图` = 不要看图；`别提示我` = 不要提示；`先不讲答案` = 先给提示。
2. 选项否定：`不是 A，是 C` 取最后一个明确选项 C；`我没选 A` 不算作答，追问「那你选的是哪一个？」。
3. 判断否定：`不是极小，是极大` 取后者；`−1 不是极小` 是对「−1 是极小」的否定，不是作答。
4. 双重意图：`不用画图，直接讲` = 完整解题；`别讲答案，给我提示` = 提示。
5. 同时出现肯定与否定且无法判定 → 只问一个澄清问题，不猜、不重复卡。
6. **实现顺序**：先查否定短语（`不用画图/别画图/不看图/不练/先不练/别提示/不要提示/直接说答案/不跳/还是讲一下`），再查肯定意图；不要只用 `includes(关键词)`，否则「不练」会命中「练」、「不用画图」会命中「图」。把否定短语做成 `NEG_PHRASES` 常量，放在 `norm()` 之后统一判断。
7. **选项否定归约**：在 `matchOption` 前加 `stripNegatedOption(t)`：`不是A，是C` → `C`；`我没选A` → 空；`不是左正右负，是左负右正` → `左负右正`。不要直接把整句丢给 `matchOption`，否则否定句会匹配失败并回到兜底卡。

**引用规则：** 回复优先引用学生这条消息里最长的一个完整短语（≤25 字）；如果消息只有选项字母，引用选项原文（「你选的是 C（x=2）」）；如果消息是空的/纯表情，用「你刚才没有输入具体内容」并给边界。

## 4. 能力边界文案

### 4.1 三段式

每条边界文案必须包含：

1. **不做什么**（一句话，具体）：不联网、不做闲聊、不覆盖这个知识点、不替你写作业。
2. **能做什么**（具体到当前题/当前按钮）：导数与极值、这道三次函数、左侧哪段示例、输入框上方哪个问题。
3. **2–3 个可继续的出口**：一个可回答的问题、一个可点的会话、一个可回看的位置。

禁止：只写「这个问题我无法回答」；把「今天天气不错」匹配回读题卡；用「谢谢/希望对你有帮助」收尾；在边界里推销无关功能。
