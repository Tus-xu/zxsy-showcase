# 01 · 体验分类与演示播放器设计

## 1. 目标

把「示例会话」从一串散落的历史记录，升级成可被主持人反复演示的 12 个体验：

- 3 道真实题图 × 4 种体验（知识问答 / 错题本 / 举一反三 / 引导式解题）。
- 每个体验是一条**预先编排、但交互真实**的对话：进入先看封面，输入框已填好第一条（文字 + 题图），用户点发送才继续；AI 真实流式回答；回答完自动填好下一条；直到走完。
- 每次重新打开该体验都从头开始，可反复演示。

## 2. 信息架构

侧栏 `/dialog` 下半区改为三段：

```
＋ 新对话
[搜索对话…]

体验分类                       ← 新增 rail
┌──────────────────────────────┐
│ 题1 双曲线离心率              │
│ [知识问答] [错题本] [举一反三] [引导式解题] │
│ 题2 正三棱柱线面关系          │
│ [知识问答] [错题本] [举一反三] [引导式解题] │
│ 题3 有放回取球期望            │
│ [知识问答] [错题本] [举一反三] [引导式解题] │
└──────────────────────────────┘

最近对话
置顶 / 今天 / 7 天内 / 更早
  每条：标题 + 类型标签 + 时间
```

- 体验 rail 固定在搜索框下方、会话列表上方；可折叠，记住折叠状态。
- rail 不依赖 `/api/agent/conversations`，直接由本地 catalog 渲染；点击 `router.push('/dialog/exp-<problem>-<mode>')`。
- 现有 6 条示例会话保留，按类型打标签（拍照解题 / 引导式 / 知识问答 / 看图讲解 / 举一反三 / 错题复盘）；最近对话仍按时间分组。
- 折叠侧栏时 rail 只显示图标/短标签，或整体隐藏（与历史列表一致）。

## 4. 播放器状态机

```
enter(expId)
  → reset(expId)                 // 清空该体验的本地进度，仅保留其它体验
  → cover                        // 显示封面 + 第 1 条预填
  → prefilled(n)                 // 输入框有内容，发送按钮可用
  → userSend(n)                  // 用户点发送：用户消息入列，清空输入
  → aiStreaming(n)               // AI 分片输出，显示光标
  → aiDone(n)
      ├─ 有交互卡：waitInteraction → 完成后 → prefilled(n+1)
      └─ 无交互卡：延迟 400ms → prefilled(n+1)
  → done                         // 最后一条 AI 完成：显示「重新体验」
```

规则：
- `enter` 时如果 URL 的 convId 与上次相同，仍重置（用户要求每次重开刷新）。
- 发送后不允许再次发送，直到 AI 完成或交互完成。
- 用户编辑预填文本：允许编辑，但脚本按「用户实际发送的文本」记录；AI 仍按脚本回答（演示模式），并在 UI 上不提示「你改了也没用」。
- 刷新页面：重新进入封面；不保留半程进度。
- 关闭/切换会话：该体验状态清空；再次进入从封面开始。
- 「重新体验」按钮：重置并重新预填第 1 条。

## 5. 与现有聊天管线的结合

优先复用 `useChat` / SSE replay，而不是另写一套消息渲染：

1. `catalog.js` 或新 `experiences.js` 提供 `isExperienceId(id)` / `getExperience(id)`。
2. `replay.js` 的 chat 分发新增 `experience` 分支：
   - 根据 `convId` + 已发送轮次，找到下一条 AI 轮；
   - 用现有 SSE 事件格式分片输出文本/卡片；
   - 记录 `experienceState[convId].cursor`。
3. `DialogView`：
   - 进入体验会话时，重置状态、渲染封面、调用 `inputRef.setDraft()` 预填；
   - `ChatInput` 增加 `setDraft(text)` / `setPrefillAttachment(asset)` / `clearDraft()` 暴露；
   - 监听 `chat.streaming` 从 true→false，若还有下一条 user 轮，延迟预填；
   - 若 AI 轮带交互卡，监听卡片的 `choose` / `interaction-submit`，完成后预填下一条，而不是走 `chat.doSend`。
4. 附件预填：
   - 体验 user 轮带 `attachment: 't1'` 时，ChatInput 显示题图缩略图 chip；
   - 发送时把题图作为 `attachments` 传入，复用现有附件渲染；
   - 不依赖文件上传 API（离线）。
5. 流式速度：
   - 复用现有分片器；体验模式可配置每片 12–24 字、20–40ms，确保 1–3 秒内看到明显流式。
6. 持久化：
   - 体验进度只放内存/`sessionStorage`；刷新重置；
   - 不写入真实 `ma_offline_demo_v1` 的会话进度，避免污染示例会话。

## 6. 视觉

- rail 卡片：白底、1px `--line`、12px 圆角；题目行显示题图缩略图（40×40，圆角 8px）+ 题号/标题/标签；四个体验 chip 为 2×2 或一行四列，选中/hover 用 `--brand-soft`。
- 封面：对话区居中的一张「体验封面」卡，含题图、标题、三条要点、`开始体验` 提示；输入框在下方已填好第一条，发送按钮高亮。
- 不对现有对话气泡做二次包装；AI 回答仍用白底描边气泡。
- rail 在 1440 宽侧栏 240px 内不换行溢出；文字用 12–13px，标签 10–11px。
- 折叠态：rail 隐藏或只显示 3 个题号按钮，title 提供全称。

## 7. 验收

- 12 个入口全部可达；每个入口的封面、首条预填、发送、流式、下一条预填、完成、重开重置都正确。
- 任一体验中途刷新，回到封面；再次进入可完整重播。
- 侧栏 1440/1920 无横向溢出；折叠态正常。
- 断网 0 请求；控制台 0 pageerror。
- 自动化：Playwright 逐个体验跑「进入 → 断言预填 → 发送 → 断言流式 → 断言下一条预填」；至少覆盖 3 个代表体验全流程 + 12 个入口 smoke。
