## 0. 这一轮为什么不是"继续改 CSS"

评审 §十 的判断是：**继续优化 CSS、美化按钮、统一卡片宽度，只会得到"更美观的固定流程系统"**。
上一轮的实现正是在既有聊天壳里叠卡片：AI 仍有气泡、每张卡带阶段徽标与"已作答"痕迹、
方法卡渲染两次、消息级引用退化成「未知来源」、进度条与卡片各说一套。
这些不是配色问题，是**产品形态**问题。

因此本轮按评审 §5.1 与 §十 的建议重做：一个独立的、以「AI 文档式教学 + 数学画布 + 专注解题」
三种形态组织的学习空间，而不是把原聊天窗美化一遍。

### 1.2 视觉问题

| 评审原文 | 处置 |
|---|---|
| 对话跨度过大，视线横移 | 阅读列固定 **720 px 居中**；学生消息最大 78% 宽；AI 内容与阅读列左缘同轴 |
| 卡片宽度不统一（400 / 1100 px） | 一切内容块不超过阅读列：题块、图组、判定块、公式块同宽 |

| 背景渐变过多 | 页面为**纯中性近白** `#fafafc`，只在输入区上方留一条极浅的淡出，无光晕、无彩色底 |

| 输入区几乎横跨页面 | 输入区与阅读列同宽同轴 |
| 上下间距过大 | 消息间距 26 px，段间距 12 px，标题上距 20 px |

### 1.3 教学交互（评审 §二 认为比视觉更重要）

| 评审原文 | 处置 |
|---|---|
| "学生已说 x=−1 让导数为零，不该再问求零点/判断局部极值/求区间最小值" | **整步删除题型选择**。开场直接回应他的真实推理：「你找到了候选点，卡在极值类型的判断」 |
| "不应把所有教学交互做成选择题" | 符号判断用**两格符号槽**（最小输入成本）；主线练习用**自由草稿**写推导；选择题在这个原型里不存在 |
| "AI 应识别学生卡在哪" | 诊断句直接点名卡点；判对后跳过已掌握步骤，转入画布；判错只给"代一个数"的小步 |
| "数学可视化不能停留在播放三张图" | 画布为**实时双向**：拖动切点 / 滑块 → f(x)、f′(x)、局部状态实时变化；可切 `f(x)=x³` 反例；AI 文字随学生操作改变 |
| "AI 要能看到学生在操作什么" | 「AI 正在看」块读取当前 `x` 与斜率并给出对应解释；**切点跨越变号位置**才触发那句关键提示（不是按按钮触发） |
| "学情沉淀应由可追溯证据生成" | 三个统计与四条证据条全部由本次会话真实操作计算：三项练习目标各自判定，未读到的项如实标"待补" |

## 2. 三个关键设计决策

### 2.1 删除"固定四步"

评审 §8 把"固定四步教学"降级为可选策略。原型的处理：

- **不预设阶段名**（读题 / 选方法 / 分步推导 / 订正一律不出现）
- 流程由**学生的实际回答**决定：答对即跳过，答错才补课
- 方法选择被取消——这道题的对数求导只有一条自然路径，把"你想先试哪种方法"当成必经步骤是编排痕迹

### 2.2 反例是判据的核心，不是补充材料

评审 §5.2 要求"从分帧动画到实时双向交互"。原型里 `f(x)=x³` 不是一张静态图，
而是**同一画布上可切换的函数**：切到原点，切线同样水平，但两侧斜率都为正。
只有学生亲手把切点拖过 `x=−1` 并看到斜率翻号，"变号才是判据"才成立。
因此那句提示的触发条件是**斜率符号跨越 0**（`prevK > 0 && nextK < 0`），
而不是"点到了 x=−1"——后者只需要运气，前者需要操作。

### 2.3 不用假数据撑场面

- 统计数字随实际作答变化：只写导数 → 1 项通过；写全 → 3 项通过
- 读不到的项写「没有读到可用于本题的导数式」，不判对也不判错
- 侧栏底部一句「AI 生成内容仅供参考 · 本地演示原型 · 不连接大模型」
- 自由输入超出脚本范围时如实说明，不假装理解

```
正文 #1b1a29   次级 #46445c   辅助 #75738c     弱化 #a4a2b8

圆角 12 / 16   阅读列 720px    侧栏 244px
正文 15/1.72   小标题 17/600   图注 12.5      公式 16.5 衬线
```
数学排版：变量斜体、真减号 `−`、独立公式左缘带 2px 品牌色竖线、行高 2.05。
不做 KaTeX 依赖——公式量小，衬线 + 上下标即可达到评审 §1.3 要求的"数学排版语言"，
且保持单文件零依赖。

## 5. 这个原型**没有**做的事（请勿当成已实现）

1. **不连接大模型**。教学对话是一条针对"把导数等于零当作极小值"这一真实错因编排的确定性路径。
   自由提问走关键词路由，读不到就如实说明。
2. 未接入真实题库、知识图谱、教师端回流。评审 §6.1 的第 9 步"学情回流教师端"未覆盖。
3. 未做"上传任意题→自动解析"。题图是本地排版素材，识别结果文案固定。
4. 掌握度证据条是**会话内证据**的展示，不是跨会话校准的掌握概率——文案已写明。
5. 知识图谱 / 课堂任务为"未展开"，不提供假页面。

## 6. 与现有系统的关系

本原型**不改正式项目代码**（评审 §十 明确建议）。它给出的是一份可直接对照实现的视觉与交互基线：
现有 Vue 组件若要向它靠拢，需要改的是「AI 消息是否用气泡」「阅读列是否受限」「卡片是否分层」
「交互是否只有选择题」这四件事，而不是换一套配色。
